# Sundogs for pi

Generated by scripts/build-distribution.mjs from registry/src/other-agents.ts. Do not edit by hand. Checked against pi 1.5.0 (@earendil-works/pi-coding-agent, docs/mcp.md, 2026-11-02).

## 1. Connect the registry (MCP)

Create an API key on your account page (https://sundo.gs/account/agents, "download" permission) and export it as `SITE_APPS_KEY` before you start the agent. Never paste it into the chat.

Put `mcp.json` from this folder in `~/.pi/agent/mcp.json` (all projects) or `.pi/mcp.json` (a trusted project), or run:

```
pi mcp add sundogs --url https://sundo.gs/mcp --bearer-token-env-var SITE_APPS_KEY
```

API key, or browser sign-in: pi identifies itself with a client metadata document, which the store accepts. For the sign-in, add the server without the key (`pi mcp add sundogs --url https://sundo.gs/mcp`), then run `/mcp login sundogs` inside pi when a tool asks for the account.

`pi mcp login` from the shell answers "Already signed in" because browsing the catalog needs no account; use `/mcp login` inside pi. Built-in MCP needs pi 0.99 or later (older `@mariozechner/pi-coding-agent` releases have none).

## 2. Add the skills

Copy the folders from `../skills/` into the project's `.agents/skills/`. Where pi reads skills and instructions: `.agents/skills/` (also `.pi/skills/`, `~/.agents/skills/`, `~/.pi/agent/skills/`); it reads `AGENTS.md`. The `AGENTS.md` section in `../codex/AGENTS.md` works for any agent that reads `AGENTS.md`.
